## Financial Field Constraint

Financial fields must NOT be accepted from the client on create or update:

| Field | Initial Value | Modified By |
|---|---|---|
| `balance` | `0.000` | Booking writes (credit balance) |
| `balance_amount` | `0.000` | Booking writes |
| `wallet` | `0.000` | Wallet deposit operations only |

Any create or update request that includes `balance`, `wallet`, or `balance_amount` must be rejected (overposting protection). These fields are server-managed exclusively.

---

## Uniqueness Rules

1. **Email**: Globally unique across all heads. The DB enforces `IX_heads_email` UNIQUE index. The handler must catch `DbUpdateException` caused by this constraint and return a `409 Conflict` (or `422 Unprocessable`) with a descriptive ProblemDetails message.
2. **UserId (agent code)**: Generated by the server for agent-type heads. The DB enforces `IX_heads_user_id` UNIQUE partial index (WHERE user_id IS NOT NULL). Format: `"AGT-{id.PadLeft(3,'0')}"`.

---

## Ownership Enforcement

- `created_by` is set by the server from the authenticated user's ID.
- Clients cannot set `created_by`.
- All read queries filter by `created_by == authenticatedUserId AND deleted_at IS NULL`.
- All write operations (update, archive) must verify `head.CreatedBy == authenticatedUserId`.

---

## Soft Delete / Archive

The `deleted_at` column exists. Archiving a head sets `deleted_at = UtcNow`. The head does not appear in list or lookup queries after archiving.

---

## External Accounts Portal

Not integrated in Phase 11. The schema has no columns referencing an external accounts portal for heads in the SQL Server schema. This integration concern is deferred.

## Status Values

From DevSeeder: `"active"`. Other expected values (from common CRM patterns and schema `nvarchar(20)` constraint): `"inactive"`, `"blocked"`. No explicit enforcement defined in Phase 11; validated as allowed set.
